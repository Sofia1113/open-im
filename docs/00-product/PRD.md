# OpenIM 产品需求文档（PRD）

> 文档版本：v0.1  
> 状态：首版基线  
> 更新时间：2026-07-28  
> 产品定位：面向熟人、团队与小型社群的跨端即时通信产品

## 1. 产品摘要

OpenIM 是一款类微信交互习惯的即时通信软件。用户可在多个设备上登录，进行单聊、群聊、文件与图片传输、多人语音/视频通话，并在会话内发送和领取虚拟红包。

首个可运行版本以 Web/PWA 客户端和独立服务端为交付物，协议层保持平台中立，后续可复用到 Electron、iOS 与 Android 客户端。演示环境中的红包余额均为虚拟资产，不连接真实支付、银行卡或法币清结算系统。

## 2. 产品目标

### 2.1 业务目标

- 建立完整、可演示的 IM 主链路：登录 → 建立会话 → 实时收发消息 → 多端同步。
- 建立完整、可演示的实时通话主链路：呼叫 → 响铃 → 接听 → 音视频切换 → 挂断。
- 建立完整、可审计的红包主链路：创建 → 发送 → 并发领取 → 查领取明细 → 过期退款。
- 为桌面端与移动端提供稳定的 REST、WebSocket 与 WebRTC 信令契约。
- 为生产化演进保留水平扩展、内容安全、风控和合规能力。

### 2.2 用户目标

- 消息发送后能立即确认状态，不因刷新或短暂掉线丢失。
- 在不同设备登录后看到一致的会话、未读数与历史消息。
- 无需安装插件即可发起小规模多人语音/视频通话。
- 红包金额、剩余份数、领取结果和退款状态清晰可信。

### 2.3 非目标（首版）

- 朋友圈、公众号、小程序、直播、视频号。
- 真实支付、提现、充值、银行卡绑定和跨境清算。
- 端到端加密密钥托管、多组织租户、企业通讯录同步。
- 超大群、万人会议、电话网关与通话录制。
- 复杂内容推荐、广告系统和商业化体系。

## 3. 名词与范围

| 名词 | 定义 |
| --- | --- |
| 客户端 | Web/PWA、Electron、iOS、Android 中的任意应用实例 |
| 设备 | 一个持久化 `deviceId` 对应的登录实例 |
| 多端在线 | 同一账号允许多个设备同时保持会话，并同步消息与状态 |
| 多人通话 | 3 人及以上在同一 RTC 房间进行语音或视频通信 |
| 会话 | 单聊或群聊的消息容器 |
| 服务端序号 | 服务端为会话内消息生成的单调递增 `seq` |
| 红包 | 由虚拟余额支付、可在会话内被一个或多个用户领取的资产对象 |

## 4. 目标用户与角色

| 角色 | 主要诉求 | 主要权限 |
| --- | --- | --- |
| 普通用户 | 聊天、通话、发送和领取红包 | 管理自己的资料、联系人、会话和设备 |
| 群成员 | 群内沟通和参与通话 | 发消息、参会、按群规则领取红包 |
| 群管理员 | 维护群秩序 | 修改群资料、管理成员、撤回违规消息 |
| 群主 | 管理群生命周期 | 管理管理员、解散群、转让群主 |
| 系统管理员 | 运营与故障处理 | 封禁账号、审计操作、处理举报，不可直接修改账务结果 |

## 6. 核心功能需求

### 6.1 身份、登录与设备

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| AUTH-01 | 用户可使用演示账号快速登录；生产环境替换为短信/邮箱/SSO | P0 |
| AUTH-02 | 服务端签发短期访问令牌和可轮换刷新令牌 | P0 |
| AUTH-03 | 同一账号允许最多 5 台设备在线，超限时用户选择下线设备 | P1 |
| AUTH-04 | 用户可查看设备名称、平台、最近活跃时间并远程退出 | P1 |
| AUTH-05 | 登录、刷新令牌、退出和远程下线均记录安全审计事件 | P1 |

### 6.2 联系人、群与会话

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| CHAT-01 | 创建单聊会话；相同两人只存在一个有效单聊会话 | P0 |
| CHAT-02 | 创建群聊、邀请/移除成员、退出/解散群 | P0 |
| CHAT-03 | 会话列表按最后活动时间排序，显示摘要、时间和未读数 | P0 |
| CHAT-04 | 支持置顶、免打扰、标记已读 | P1 |
| CHAT-05 | 单群首版上限 200 人，群名称 2–50 字符 | P1 |

### 6.3 消息

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| MSG-01 | 支持文本、图片、文件、系统通知、通话记录和红包卡片 | P0/P1 |
| MSG-02 | 客户端使用 `clientMessageId` 幂等发送，服务端返回消息 ID 与 `seq` | P0 |
| MSG-03 | 消息状态至少包含发送中、已发送、发送失败；单聊支持已读回执 | P0 |
| MSG-04 | 断线重连后按会话游标拉取缺失消息，不能只依赖在线推送 | P0 |
| MSG-05 | 支持最近 2 分钟内撤回自己的普通消息，并广播系统消息 | P1 |
| MSG-06 | 图片与文件先上传对象存储，再发送包含受控资源标识的消息 | P1 |
| MSG-07 | 服务端对消息内容、大小、频率和成员身份做校验 | P0 |

首版限制：文本最多 4,000 字符；图片单文件 20 MB；普通文件 100 MB；消息历史默认保留 365 天（部署方可配置）。

### 6.4 多端同步

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| SYNC-01 | 用户在设备 A 发送的消息实时同步到设备 B | P0 |
| SYNC-02 | 已读游标、会话置顶、免打扰在账号各端同步 | P1 |
| SYNC-03 | 接听设备确认后，其他设备上的响铃立即停止 | P0 |
| SYNC-04 | 红包领取结果与钱包流水在各端保持一致 | P0 |
| SYNC-05 | 离线设备上线时先同步游标差异，再进入实时流 | P0 |

### 6.5 语音与视频通话

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| CALL-01 | 单聊可发起一对一语音或视频通话 | P0 |
| CALL-02 | 群聊可选择成员发起 2–6 人的小型多人通话 | P0 |
| CALL-03 | 入会前预览摄像头、麦克风和扬声器状态 | P1 |
| CALL-04 | 通话中可静音、关闭摄像头、切换音频/视频设备和离会 | P0 |
| CALL-05 | 支持邀请、响铃、接听、拒绝、忙线、取消和超时 | P0 |
| CALL-06 | 服务端只转发 SDP/ICE 信令，不接触端到端媒体内容 | P0 |
| CALL-07 | 记录发起人、参与人、开始/结束时间和结束原因，不录制媒体 | P1 |
| CALL-08 | 弱网下展示连接状态，ICE 失败时允许重试 | P1 |

首版浏览器采用 WebRTC Mesh，建议最多 6 人；生产环境超过 6 人应接入 LiveKit/mediasoup 等 SFU，业务层房间和权限模型保持不变。

### 6.6 红包与虚拟钱包

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| RED-01 | 单聊可发送定额红包；仅对方可领 | P0 |
| RED-02 | 群聊可发送等额或随机金额红包 | P0 |
| RED-03 | 红包份数不得超过当前群成员数，发起人可配置是否可领取 | P0 |
| RED-04 | 领取操作幂等；高并发下不得超领、重复领或产生负余额 | P0 |
| RED-05 | 红包卡片实时展示待领取、已领完、已过期、已退款状态 | P0 |
| RED-06 | 24 小时未领金额自动退回发送者虚拟余额 | P0 |
| RED-07 | 每次余额变化生成不可变账务流水，红包明细可审计 | P0 |
| RED-08 | 支持单笔、单日金额与频次限制以及异常冻结 | P1 |

默认演示规则：金额以整数分存储；单个红包 1–20,000 分；1–100 份；24 小时过期。随机红包采用“剩余金额与剩余份数约束”算法，保证每份至少 1 分且最终总额精确相等。

### 6.7 通知与在线状态

- 在线时通过 WebSocket 接收消息、回执、通话邀请和红包状态变更。
- 浏览器后台通过 Web Notification 提醒；移动端后续接 APNs/FCM/厂商推送。
- 在线状态只提供“在线/最近在线”的粗粒度结果，受用户隐私设置约束。
- 免打扰会话仍同步事件，但不触发声音与系统通知。

### 6.8 管理与风控

- 管理端可冻结账号、踢下线、查看安全审计和处理举报。
- 敏感操作必须保留操作者、目标、原因、时间、来源 IP 与请求 ID。
- 账务纠错使用冲正流水，不直接更新或删除历史流水。
- 服务端应支持敏感词、文件类型、消息频率和红包频率策略接口。

## 7. 核心用户流程

### 7.1 发送消息

1. 客户端生成全局唯一 `clientMessageId` 并本地展示“发送中”。
2. 通过 WebSocket 提交消息命令；若离线则进入本地待发队列。
3. 服务端校验身份、成员资格、内容与幂等键，写入数据库并生成 `seq`。
4. 服务端向发送者所有设备 ACK，并向会话成员在线设备推送。
5. 客户端按 `seq` 去重、补洞和排序；失败时允许使用同一幂等键重试。

### 7.2 发起多人通话

1. 发起人在群会话选择成员和通话类型。
2. 服务端创建房间、校验成员，向被邀请人的所有在线设备响铃。
3. 某一设备接听后，服务端通知该账号其他设备停止响铃。
4. 参与端加入 WebRTC 房间并交换 SDP/ICE；首版由浏览器建立 Mesh 连接。
5. 所有人离开或房间超时后服务端结束房间并写入通话记录消息。

### 7.3 发送和领取红包

1. 发送者输入总金额、份数、分配模式和祝福语。
2. 服务端在数据库事务中校验余额并冻结/扣减金额，创建红包和预分配份额。
3. 红包创建成功后发送红包消息卡片；消息失败时通过补偿任务确保可见或退款。
4. 领取者提交幂等请求；服务端锁定红包/份额并写入领取记录和账务流水。
5. 红包领完后广播状态；过期任务将剩余金额以退款流水返还发送者。

## 8. 非功能要求

| 类别 | 首版目标 | 生产目标 |
| --- | --- | --- |
| 消息延迟 | 本地网络 P95 < 500 ms | 同地域 P95 < 300 ms |
| 可用性 | 单实例可恢复 | 核心消息服务月可用性 99.95% |
| 一致性 | 消息最终一致、账务强一致 | 同左，支持跨实例和故障恢复 |
| 容量 | 100 并发连接、10 msg/s 演示 | 按压测水平扩展至 100k+ 连接 |
| 安全 | HTTPS/WSS、鉴权、限流、输入校验 | KMS、WAF、审计、密钥轮换、风控 |
| 可观测性 | 结构化日志、健康检查、请求 ID | 指标、链路追踪、SLO 与告警 |
| 兼容性 | Chrome/Edge/Safari 最近两个大版本 | 增加 iOS/Android/Electron 矩阵 |
| 无障碍 | 键盘可操作、基础语义标签 | WCAG 2.1 AA |

## 9. 成功指标

- 消息发送成功率 ≥ 99.9%，重连补消息成功率 100%（自动化场景）。
- 一对一通话建立成功率 ≥ 98%（受控网络）；6 人房间可稳定运行 20 分钟。
- 红包并发测试中超领数、重复领取数和账务不平数均为 0。
- 核心任务完成率：首次发消息 ≥ 90%，成功接听通话 ≥ 85%，成功领取红包 ≥ 95%。
- 客户端崩溃率 < 0.5%，服务端未处理异常为 0。

## 10. 发布分期

### M0：文档与工程基线

产品范围、架构、数据模型、事件契约、代码规范和本地开发环境。

### M1：可演示 MVP

演示登录、会话列表、实时文本消息、小型 WebRTC 音视频房间、虚拟红包、基础多端同步。

### M2：业务可用

好友/群管理、图片文件、消息回执与撤回、TURN、Redis、PostgreSQL、对象存储、通知和管理审计。

### M3：生产化

SFU、移动/桌面客户端、离线推送、内容审核、灾备、压测、安全与合规验收。

## 11. 产品决策与待确认项

当前基线采用以下可替换决策：

- 产品面向通用消费者/小团队，不引入企业多租户。
- 首版采用虚拟余额；接真实资金前必须重新完成支付牌照、实名、反洗钱、风控、清结算与财务审计设计。
- 首版群上限 200，Mesh 通话上限 6；二者不是生产规模承诺。
- 服务端默认可读取消息明文以支持审核；端到端加密作为独立版本规划。
- 演示登录只用于本地环境，禁止直接暴露到公网生产环境。
