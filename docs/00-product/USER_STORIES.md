# 用户故事、业务规则与异常场景

## 2. Given / When / Then 验收场景

### US-MSG-01 幂等发送消息

- Given Alice 已登录并属于会话 C。
- When Alice 以相同 `clientMessageId` 重试发送 3 次。
- Then 服务端只创建 1 条消息并在每次响应中返回相同 `messageId` 和 `seq`。

### US-MSG-02 断线补偿

- Given Bob 已同步至 `seq=20`，随后断网，期间会话产生 5 条消息。
- When Bob 重连并携带 `afterSeq=20`。
- Then Bob 收到 `seq=21..25`，随后再接收实时事件，不重复、不缺失。

### US-CALL-01 多设备接听

- Given Bob 的手机和网页均在线并收到 Alice 的呼叫。
- When Bob 在手机接听。
- Then 网页停止响铃并显示“已在其他设备接听”，Alice 进入通话。

### US-CALL-02 权限失败

- Given 用户拒绝浏览器麦克风权限。
- When 用户尝试加入语音通话。
- Then 客户端保留房间页面，给出开启权限的可执行说明，不伪装为已入会。

### US-CALL-03 网络恢复

- Given 通话中 ICE 连接进入 `disconnected`。
- When 10 秒内网络恢复。
- Then 客户端触发 ICE restart；成功后继续计时，失败则展示重试或离会。

### US-RED-01 并发领取

- Given 一个 10 份红包仍有 1 份，20 名有资格用户同时请求领取。
- When 服务端并发处理请求。
- Then 恰好 1 人成功，19 人得到“已领完”，账务借贷总额相等。

### US-RED-02 重复领取

- Given Alice 已领取红包 R。
- When Alice 以相同或不同幂等键再次领取 R。
- Then 返回 Alice 原领取结果，不新增份额和账务流水。

### US-RED-03 过期与领取竞争

- Given 红包在当前时刻到期，领取请求与过期任务并发执行。
- When 两者争用同一红包。
- Then 每一份金额只能进入“已领取”或“已退款”之一，不能同时发生。

## 3. 业务规则表

### 3.1 会话与消息

- 只有有效成员可拉取和发送会话消息。
- 会话内 `seq` 严格递增；不同会话之间不承诺全局顺序。
- 服务端写入成功才视为已发送；WebSocket 推送不是事实来源。
- `clientMessageId` 在“发送者 + 设备/账号”范围内唯一，至少保留到消息数据过期。
- 客户端遇到序号缺口必须调用同步接口，不得直接假定消息永久丢失。
- 撤回不物理删除原记录，而是写撤回状态并广播可审计事件。

### 3.2 通话

- 呼叫者必须是会话成员，被邀请者必须是该会话有效成员。
- 同一账号同一时刻最多参与一个活跃通话；再次被呼叫返回忙线。
- 邀请默认 45 秒超时；房间无人 60 秒后结束。
- 通话类型可从视频降级为纯音频；从音频升级视频需要本端权限，但无需重建业务房间。
- 信令事件带 `roomId`、`participantId` 和递增/唯一标识，过期房间事件必须忽略。

### 3.3 红包

- 所有金额使用整数最小货币单位，禁止浮点数。
- 发红包前检查账户状态、可用余额、限额、会话成员关系和幂等键。
- 红包发布后总金额和份数不可修改。
- 单聊红包的领取者固定为对方；群红包按发送时群成员快照或领取时成员资格校验，首版采用领取时资格校验。
- 同一用户同一红包只能成功领取一次。
- 领取结果落库后不可修改；纠错通过补偿/冲正流水。
- 领取成功与余额入账属于同一数据库事务。
- 发红包扣款成功但消息发布失败时，可靠事件任务负责重发；超过补偿期限则关闭并全额退款。

## 4. 状态机

### 4.1 消息状态

`LOCAL_PENDING → SENT → DELIVERED/READ`

异常分支：`LOCAL_PENDING → FAILED → LOCAL_PENDING`；已发送消息可变为 `RECALLED`。

### 4.2 通话房间状态

`INVITING → RINGING → ACTIVE → ENDED`

提前终止：`INVITING/RINGING → CANCELED | REJECTED | TIMEOUT | FAILED`。

### 4.3 红包状态

`CREATED → PUBLISHED → PARTIALLY_CLAIMED → EXHAUSTED`

过期分支：`PUBLISHED/PARTIALLY_CLAIMED → EXPIRED → REFUNDED`。

## 5. 空态、错误与降级

| 场景 | 用户反馈 | 客户端行为 | 服务端行为 |
| --- | --- | --- | --- |
| WebSocket 断开 | 顶部显示“正在重连” | 指数退避，消息进入待发队列 | 保留会话事实，恢复后支持补拉 |
| 消息被拒绝 | 消息旁显示失败原因 | 允许编辑或重试 | 返回稳定错误码，不写入消息 |
| 摄像头不可用 | 展示权限/设备提示 | 默认以音频加入 | 不改变房间合法性 |
| ICE 失败 | 展示“连接失败” | 尝试 ICE restart 或离会 | 记录质量事件，不伪造通话成功 |
| 红包已领完 | 展示已领完和明细 | 禁用再次领取 | 返回当前红包摘要 |
| 红包请求超时 | 展示“结果确认中” | 用幂等键查询结果 | 保证重试返回同一结果 |
| 余额不足 | 表单内提示 | 不创建本地成功卡片 | 不扣款、不创建红包 |
