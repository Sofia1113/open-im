# 安全、隐私与合规基线

## 1. 威胁模型

重点防护对象包括账号令牌、消息与附件、通讯关系、音视频网络元数据、虚拟余额/红包和管理权限。主要威胁包括撞库与盗号、越权读取会话、WebSocket 伪造事件、XSS/恶意文件、通话信令滥用、红包并发套利、管理员越权及敏感日志泄漏。

## 2. 身份与会话

- 生产登录使用短信/邮箱/SSO 并具备频率限制与风险验证；演示登录只允许本地环境。
- 访问令牌短期有效，刷新令牌按设备保存哈希并每次轮换；重用旧令牌触发设备会话撤销。
- WebSocket 握手和每个敏感命令都校验身份；远程退出立即断开对应连接。
- 密钥通过 KMS/Secret Manager 管理，禁止写入仓库、前端包、镜像层或日志。
- 管理后台使用独立身份域、MFA、最小权限和短会话。

## 3. 授权

- 每次访问会话、消息、通话或红包都以服务端成员关系为准，不信任客户端传入角色。
- 查询不存在与无权限资源时避免泄露资源是否存在。
- 群管理员权限不能隐式获得钱包/账务权限。
- 对象存储使用短期签名上传/下载 URL，资源 key 不等于授权。

## 4. 输入与内容安全

- Spring Bean Validation 校验 HTTP/WebSocket DTO，Web 客户端使用 TypeScript 契约，并设置正文、数组、SDP/ICE 大小上限。
- 消息展示使用 React 文本转义，禁止未经清洗的 HTML；链接使用安全协议白名单。
- 上传检查扩展名、MIME、文件头、大小与恶意内容；下载使用正确 `Content-Disposition`。
- 对登录、发消息、建群、呼叫、信令、发/领红包分别限流。
- SQL 使用参数化查询；错误响应不返回堆栈、SQL、密钥或内部拓扑。

## 5. 网络与音视频

- 生产强制 HTTPS/WSS、HSTS 和安全 TLS 配置。
- WebRTC 默认使用 DTLS-SRTP 加密媒体；TURN 使用短期凭证和 `turns:` 选项。
- 不持久化 SDP/ICE，不在日志记录完整 IP；质量统计使用最小化与匿名化数据。
- 配置 CSP、`Permissions-Policy` 和可信源，限制摄像头/麦克风权限范围。

## 6. 钱包与红包

- 金额整数化、数据库约束、事务、唯一幂等键和不可变流水缺一不可。
- 管理员无直接改余额接口；补偿使用可审计冲正交易。
- 限额和风险策略必须在服务端执行，且关键结果进入审计。
- 定期运行账户/红包对账，发现不平立即冻结相关业务并告警。

## 7. 隐私

- 明确收集目的、保留期限和删除/导出流程；默认只收集实现功能所需数据。
- 在线状态、已读回执和通话质量统计提供可理解的隐私说明与设置。
- 通知预览遵守用户设置，锁屏默认不显示红包金额等敏感内容。
- 分析/日志标识使用脱敏 ID；生产数据不得直接复制到测试环境。
- 账号删除应处理个人资料匿名化，但依法/账务所需的不可变记录按政策保留。

## 8. 审计与响应

- 登录、设备变更、封禁、群管理、账务交易、冲正和策略变更写只追加审计日志。
- 审计访问本身也被审计；定期复核管理员权限。
- 建立令牌泄漏、越权、账务不平、恶意文件和通话滥用的应急预案。
- 备份加密，定期恢复演练；定义 RPO/RTO 并验证而非只声明。

## 9. 上线前检查

- 依赖与镜像漏洞扫描、SAST、密钥扫描、SBOM。
- 认证/授权、IDOR、XSS、CSRF/CORS、上传、限流和 WebSocket 渗透测试。
- 红包并发、幂等、故障恢复和对账专项评审。
- TURN/SFU 安全配置、带宽滥用限制与隐私评审。
- 隐私政策、用户协议、数据保留和目标地区合规确认。
