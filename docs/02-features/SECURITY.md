# 安全、隐私与合规基线

## 1. 威胁模型

重点防护对象包括账号令牌、消息与附件、通讯关系、音视频网络元数据、虚拟余额/红包和管理权限。主要威胁包括撞库与盗号、越权读取会话、WebSocket 伪造事件、XSS/恶意文件、通话信令滥用、红包并发套利、管理员越权及敏感日志泄漏。

## 2. 身份与会话

> **当前实现**：已支持用户名/邮箱 + 密码登录（BCrypt cost 12）、连续失败锁定、
> 账号枚举防护。短信/邮箱验证码、SSO 和 MFA 尚未实现——它们需要外部 provider，
> 当前无法接入也无法测试。凭证存储、失败锁定、审计与限流这套基础设施对三种
> 验证方式共用，接入新方式是增加一个 identity provider，而不是重做。
> 密码找回流程同样未实现，这意味着**用户忘记密码后目前只能由管理员直接操作数据库重置**。

- 生产登录使用短信/邮箱/SSO 并具备频率限制与风险验证；演示登录只允许本地环境。
- 密码哈希使用自适应算法并保留升级路径；只存哈希，不存明文或可逆加密值。
- 登录失败计数与账号锁定存储在不可降级的存储（数据库）中，
  不建立在故障时会放行的组件之上。
- 认证失败响应对"账号不存在"与"密码错误"完全一致，且两条路径的计算开销等价，
  避免通过响应内容或响应时间枚举账号。
- 访问令牌短期有效，刷新令牌按设备保存哈希并每次轮换；重用旧令牌触发设备会话撤销。
- WebSocket 握手和每个敏感命令都校验身份；远程退出立即断开对应连接。
- 密钥通过 KMS/Secret Manager 管理，禁止写入仓库、前端包、镜像层或日志。
- 管理后台使用独立身份域、MFA、最小权限和短会话。

## 3. 授权

- 每次访问会话、消息、通话或红包都以服务端成员关系为准，不信任客户端传入角色。
- 查询不存在与无权限资源时避免泄露资源是否存在。
- 群管理员权限不能隐式获得钱包/账务权限。
- 对象存储使用短期签名上传/下载 URL，资源 key 不等于授权。

## 4. 输入与内容安全

- Spring Bean Validation 校验 HTTP/WebSocket DTO，Web 客户端使用 TypeScript 契约，并设置正文、数组、SDP/ICE 大小上限。
- 消息展示使用 React 文本转义，禁止未经清洗的 HTML；链接使用安全协议白名单。
- 上传检查扩展名、MIME、文件头、大小与恶意内容；下载使用正确 `Content-Disposition`。
- 对登录、发消息、建群、呼叫、信令、发/领红包分别限流。
- SQL 使用参数化查询；错误响应不返回堆栈、SQL、密钥或内部拓扑。

## 5. 网络与音视频

- 生产强制 HTTPS/WSS、HSTS 和安全 TLS 配置。
- WebRTC 默认使用 DTLS-SRTP 加密媒体；TURN 使用短期凭证和 `turns:` 选项。
- 不持久化 SDP/ICE，不在日志记录完整 IP；质量统计使用最小化与匿名化数据。
- 配置 CSP、`Permissions-Policy` 和可信源，限制摄像头/麦克风权限范围。

## 6. 钱包与红包

- 金额整数化、数据库约束、事务、唯一幂等键和不可变流水缺一不可。
- 管理员无直接改余额接口；补偿使用可审计冲正交易。
- 限额和风险策略必须在服务端执行，且关键结果进入审计。
- 定期运行账户/红包对账，发现不平立即冻结相关业务并告警。

## 7. 隐私

- 明确收集目的、保留期限和删除/导出流程；默认只收集实现功能所需数据。
- 在线状态、已读回执和通话质量统计提供可理解的隐私说明与设置。
- 通知预览遵守用户设置，锁屏默认不显示红包金额等敏感内容。
- 分析/日志标识使用脱敏 ID；生产数据不得直接复制到测试环境。
- 账号删除应处理个人资料匿名化，但依法/账务所需的不可变记录按政策保留。

### 7.1 数据主体权利的实现状态

**删除权（已实现）**：`DELETE /api/v1/account`，需提供当前密码
（不可逆操作不能只凭访问令牌授权）。实现方式是**匿名化而非物理删除**——
`users` 被 14 处外键引用，硬删除会破坏账务完整性或让他人的会话历史出现空洞。

| 数据 | 处理 | 依据 |
| --- | --- | --- |
| 用户名 | 替换为 `deleted_<id前8位>` | 非空唯一约束要求有值 |
| 昵称 / 头像 | 替换为占位 | — |
| 邮箱 | 置 NULL | 唯一索引带 `status <> 'DELETED'` 条件，释放给新注册 |
| 密码凭证 | **整行删除** | 保留已注销账号的哈希只是多一份可离线破解的材料 |
| 设备会话 / 重置令牌 | 删除 | — |
| 账务流水 | **保留** | 删除会让借贷不平、总额不守恒；属"存在法律义务需保留的数据" |
| 消息正文 | **保留**，发送者已匿名化 | 群聊与单聊消息同时是**其他参与者**的通信记录 |
| 审计日志 | **保留** | 合规依据；`actor_id` 保留可追溯性但已不指向可识别信息 |

> **"消息正文保留"这一条有法律含义，上线前必须由法务确认。**
> 不同司法辖区对通信记录的共同所有权认定不同，删除他人会话中的历史内容
> 与保留已注销用户的内容之间没有普适答案。当前选择偏向"不在他人会话里留下空洞"。
>
> 钱包余额非零时拒绝注销：那笔钱注销后既不属于任何人、又还在账务总额里，
> 对账时会成为无法解释的余额。真实支付场景下这一步应该是提现或退回。

**访问权 / 导出（未实现）**：没有"导出我的数据"接口。用户可以通过既有接口
读到自己的会话与消息，但没有一次性的结构化导出。

**更正权（部分）**：可改密、可改昵称；邮箱变更接口未实现。

### 7.2 IP 地址的处理

`audit_logs.ip_hash` 存 SHA-256(部署盐 + IP) 的前 128 位，不存明文。

**盐值是必需的**：IPv4 只有 2³² 个地址，无盐哈希可以在普通机器上几分钟内
全量枚举建成彩虹表，届时"哈希"提供的隐私保护为零。
盐固定而非每条随机，因为审计的用途是"找出同一来源的多次操作"——
这是可链接性与不可还原性之间的取舍，审计场景需要前者。

未单独配置时从 JWT 签名密钥派生。**轮换签名密钥会使历史审计记录的 IP 哈希
不再可比对**，需要跨轮换保持可链接性时应显式配置 `openim.audit.ip-hash-salt`。

## 8. 审计与响应

- 登录、设备变更、封禁、群管理、账务交易、冲正和策略变更写只追加审计日志。
- 审计访问本身也被审计；定期复核管理员权限。
- 建立令牌泄漏、越权、账务不平、恶意文件和通话滥用的应急预案。
- 备份加密，定期恢复演练；定义 RPO/RTO 并验证而非只声明。

### 8.1 当前实现状态

**已覆盖**：认证全链路（登录成功/失败、锁定、令牌重放、改密、重置、注销）、
资金操作（红包发放/领取/退款）、设备撤销。资金类审计（`wallet.*` / `red_packet.*`）
不参与保留期清理——账务追溯期远长于一般操作日志。

**审计表按月分区**（`audit_logs`），保留期删除是 `DROP PARTITION` 而非 `DELETE`。
删除**默认关闭**：审计数据的保留期由合规要求决定，不该由一个默认开启的
定时任务执行；每次删除都会记 WARN 日志——静默删除审计数据是不可接受的。

**尚未覆盖**：
- 审计访问本身未被审计（没有查询审计的接口，因此也没有它的访问记录）
- 无管理后台，因此没有管理员操作的审计
- 群成员管理尚未实现，对应的审计也不存在

**应急预案与响应**：令牌重放已自动处置（撤销对应设备）并有告警；
账务不平有对账查询与告警规则。处置步骤见
[值班手册](../../deploy/observability/RUNBOOK.md)。

**RPO/RTO**：目标 RPO 5 分钟 / RTO 1 小时，**当前实际 RPO 是 24 小时**
（每日全量备份，PITR 需要 WAL 归档且尚未配置）。RTO 演练实测约 15 分钟。
备份**尚未加密**且与数据库同区域。详见
[备份与恢复](../../deploy/observability/BACKUP.md)。
