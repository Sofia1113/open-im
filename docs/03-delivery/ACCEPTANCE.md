# MVP 验收与测试方案

## 1. 验收环境

- Java 21+、Maven 3.9、Node.js 22、pnpm 10。
- Chrome 最近稳定版，允许开启两个普通/无痕窗口模拟不同用户。
- 本地服务端和 Web 客户端；摄像头/麦克风仅在 localhost 或 HTTPS 下可用。
- 演示账号：Alice、Bob、Carol；每个账号初始虚拟余额由种子数据提供。

## 2. 启动验收

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| ENV-01 | 按 README 安装依赖并启动 | Web 和 API 均无构建错误 |
| ENV-02 | 请求 `/health` | 返回 `ok`、版本和启动时间 |
| ENV-03 | 执行测试与类型检查 | 全部通过，无未处理 Promise/异常 |

## 3. P0 功能验收

### 3.1 登录与消息

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| MSG-01 | Alice、Bob 分别登录并打开单聊 | 双方看到相同会话身份 |
| MSG-02 | Alice 连续发送 3 条文本 | Alice 得到 ACK，Bob 实时按序收到 |
| MSG-03 | 断开 Bob 网络后发送，再恢复 | Bob 补齐缺失消息且不重复 |
| MSG-04 | 重复提交相同 `clientMessageId` | 服务端仅存在一条消息 |
| MSG-05 | 非成员构造会话 ID 发消息 | 返回 `NOT_A_MEMBER/FORBIDDEN`，无人收到 |
| MSG-06 | 超长/空文本 | 客户端提示且服务端拒绝非法载荷 |

### 3.2 多端同步

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| SYNC-01 | Alice 同时打开两个标签页 | 任一页发送后两页均出现一次 |
| SYNC-02 | 一端更新已读游标 | 另一端未读状态收敛（M1 可为基础实现） |
| SYNC-03 | 一端接听呼叫 | 同账号其他端立即停止响铃 |

### 3.3 音视频

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| RTC-01 | Alice 向 Bob 发起语音通话 | Bob 响铃，可接听/拒绝/超时 |
| RTC-02 | Bob 接听 | 双方收到远端音频并看到正确状态 |
| RTC-03 | 视频通话关闭/开启摄像头 | 连接不重建，UI 和轨道状态一致 |
| RTC-04 | 3 个用户加入群通话 | 每人可接收其他两人的媒体 |
| RTC-05 | 用户拒绝设备权限 | 展示可操作错误，不进入虚假通话 |
| RTC-06 | 一人挂断 | 其他参与者状态更新；最后一人离开后房间结束 |

### 3.4 红包

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| RED-01 | Alice 在单聊发 100 分红包 | Alice 扣 100 分，仅 Bob 可领 |
| RED-02 | Bob 领取并重复点击 | 只入账一次，重复返回原结果 |
| RED-03 | 群内发 5 份 1,000 分随机红包 | 5 份均 ≥1 分，合计 1,000 分 |
| RED-04 | 多人竞争最后一份 | 恰好一人成功，无负数、无超领 |
| RED-05 | 余额不足或金额越界 | 不创建红包、不扣余额 |
| RED-06 | 红包过期 | 未领金额精确退款，不能继续领取 |
| RED-07 | 刷新或另一端查看 | 红包状态、领取明细、余额一致 |

## 4. API 与安全验收

- 缺少/伪造令牌访问受保护 API 返回 401。
- 修改 `userId/conversationId/roomId/redPacketId` 不能越权读取或操作。
- HTTP 与 WebSocket 非法载荷返回稳定错误码，进程不崩溃。
- 日志检查不含令牌、完整 SDP/ICE、消息正文和敏感账务信息。
- 通话和红包端点具备合理频率限制（生产实现阶段）。
- 依赖审计无已知高危漏洞，或有记录清晰的风险接受与升级计划。

## 5. 自动化测试分层

| 层级 | 范围 | 必测内容 |
| --- | --- | --- |
| 单元 | 领域服务/纯函数 | 随机份额、状态机、验证、幂等 |
| 集成 | API + 仓储 | 登录、消息事务、领取与退款 |
| WebSocket | 实时网关 | 鉴权、ACK、扇出、信令授权 |
| E2E | 浏览器 | 两用户消息、呼叫、红包主路径 |
| 并发 | 红包/消息 | 最后一份竞争、重复请求、序号唯一 |
| 恢复 | 断线/重启 | 游标补拉、Outbox 重放、退款重试 |

## 6. 性能基线

- 单实例 100 个 WebSocket 连接保持 10 分钟，无持续内存增长。
- 10 msg/s 持续 5 分钟，ACK P95 < 500 ms（本机参考值）。
- 100 个并发请求竞争 10 份红包，无超领，接口结果在 5 秒内收敛。
- 6 人 Mesh 在目标测试设备运行 20 分钟；记录 CPU、上行带宽、丢包和失败率。

## 7. 发布阻断条件

出现以下任一问题不得标记 M1 完成：

- 消息永久丢失、重复持久化或会话内序号冲突。
- 未授权用户可以读取消息、加入通话或领取红包。
- 红包超领、重复入账、负余额或金额不守恒。
- 通话结束后摄像头/麦克风轨道仍在采集。
- 服务端重启/错误后无法明确告知演示数据边界。
- 仓库包含真实密钥、令牌或用户数据。
